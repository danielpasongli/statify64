## KEPUTUSAN TERBUKA / risiko
1. **Prasyarat I1** berstatus "SELESAI SEBAGIAN"; saya lanjut karena yang belum terbukti hanya jest, dan ketiga ekspor sudah diverifikasi ada serta berjalan. Bila pemilik menganggap ini pelanggaran prasyarat, fase ini perlu dijalankan ulang setelah I1 hijau di jest.
2. Kalimat pengecualian evaluasi ditempel ke akhir paragraf `Note.` milik fungsi NB lewat manipulasi string (`appendNote`). Bila I1/NB mengubah format akhir HTML (paragraf Note tidak lagi di akhir), kalimat dibuat sebagai Note baru, jadi tidak rusak, tetapi bisa ada dua paragraf Note.
3. Panjang 60–220 kata: Metrics dengan kelas tidak seimbang plus kalimat pengecualian bisa mendekati batas atas; teruji untuk kasus fixture dan kasus tidak seimbang (tanpa uji panjang untuk kasus ekstrem).
4. Nilai parameter dari Rust (`Text source`, `Text likelihood`) tetap tampil huruf kecil di tabel Model Summary (`multinomial`); hanya di `description` nama likelihood diberi huruf kapital. Mengubahnya berarti menyentuh nilai dari Rust (milik R2) atau perilaku formatter.
5. Pemetaan vektor di `description` Model Summary dibaca dari baris `Word-Vector Columns` di tabel (regex atas teks kanonik), karena `resultApplyModel` tidak menerima `textMapping`. Menambah field itu ke payload berarti mengubah `apply-model-analysis.ts` (bukan milik I2).
6. `Rows with empty text` dan jumlah kolom nol-terisi dibaca dari `model_summary.parameters` hasil Rust; bila WASM lama mengirim label berbeda, kalimat terkait dilewati (tidak error).
7. Pesan `warnings[].message` pada fixture masih Indonesia (milik R2); tidak dipakai oleh output tabel ini.
