## KEPUTUSAN TERBUKA / risiko
1. **Dua test lama harus berubah input-nya (butuh persetujuan pemilik, sama seperti keputusan A1 #1).** `scoring/naive_bayes.rs::error_schema_version_unsupported` dan `wasm/function.rs::model_errors_are_propagated_with_their_code` memakai `"2.0"` sebagai contoh "versi tak didukung". Karena 2.0 kini wajib didukung, literal diganti `"3.0"` (kode error yang diharapkan `AM_E_SCHEMA_VERSION_UNSUPPORTED` tidak berubah).
2. **Signature konstruktor WASM menambah argumen ke-7 `text` (opsional).** Pemanggil lama dengan 6 argumen tetap valid. Worker `apply-model.worker.js` perlu meneruskan payload Text (milik I1) dan `apply-model-analysis.ts` membangunnya (milik A3). Bentuk payload mengikuti §10.3; `mapped_columns` = indeks ke `model.text.columns`, `values[row][j]` sejajar `mapped_columns`.
3. **Model tanpa Text yang menerima payload Text berlebih: payload diabaikan** (konservatif, tidak mengubah perilaku v1). Sebaliknya model dengan Text tanpa payload → `AM_E_PAYLOAD`. Bila A3 lebih suka error untuk kasus pertama, ubah di `function.rs` (`(None, _) => None`).
4. **Baris ringkasan Text diletakkan di `model_summary.parameters`** (label/nilai) agar tidak mengubah tipe TS `ApplyModelRawResult`: `Text source`, `Text likelihood`, `Text features zero-filled` (hanya vector), `Rows with empty text` (hanya raw). A3 menampilkannya apa adanya atau memformatnya.
5. **Teks missing pada baris yang tetap diskor dihitung sebagai prediktor missing** (`rows_with_missing_predictor` bertambah). Ini tafsiran V11 ("teks kosong dihitung prediktor missing"); AGENTS_V2 tidak menyebut kolom ringkasan ini secara eksplisit.
6. **Vector: nilai non-finite diperlakukan seperti null** untuk penentuan "ada nilai" (K5) dan menjadi 0 saat skor; AGENTS_V2 §10.4 hanya menyebut `null`. Payload dari TS (JSON) tidak bisa membawa NaN, jadi dampaknya hanya pada pemanggil Rust langsung.
7. **Pesan `AM_E_TEXT_NEGATIVE`:** detail = nama kolom model pertama (menurut urutan `mapped_columns`), ditambah ` (total {n} kolom bermasalah)` bila n > 1. Nama kolom dataset tidak tersedia di payload §10.3 sehingga tidak disebut. Template TS A1 membungkus detail di dalam tanda kutip (`'{detail}'`) sehingga untuk n > 1 tampil `'VEC_a (total 3 kolom bermasalah)'` — janggal tetapi informatif; A3/pemilik dapat menyesuaikan template.
8. **Validasi lapis kedua Rust lebih ketat daripada adapter TS A1** (`uses_class_prior`, tanda `log_weights`, `doc_freq`): model buatan tangan yang lolos TS bisa ditolak Rust dengan kode `AM_E_NB2_LIKELIHOOD` (konsistensi prior) / `AM_E_FIELD_TYPE` (tanda bobot) / `AM_E_NB2_TEXT_SHAPE` (`doc_freq`). Disarankan A3/pemilik menambah pemeriksaan `uses_class_prior` di adapter TS (REVIEW-G1 A1-3); bukan milik fase ini. Pemeriksaan `variance ≥ min_variance` untuk `gaussian_minstd` sengaja tidak ditambahkan (tidak diminta; menghindari penolakan keliru).
9. **Normalisasi float-bulat pada resep:** nilai seperti `2.0` yang tiba dari JS (field `u32`/`usize`: `doc_freq`, `n_docs`, `ngram_*`, `words_to_keep`, `min_term_freq`) diubah ke bilangan bulat sebelum `from_value` (`normalize_integers`, diuji `resep_dengan_bilangan_bulat_bertipe_float_tetap_terbaca`). Tanpa ini deserialisasi bisa gagal bergantung pada perilaku `serde_wasm_bindgen`.
10. **`TextValues` memakai enum `untagged`** (bukan `tag = "source"`) karena enum internally-tagged mem-buffer bilangan bulat dan dapat gagal lewat `serde_wasm_bindgen`. Kecocokan `source` dan bentuk `values` diperiksa di `prepare` (`AM_E_PAYLOAD`). Perilaku deserialisasi lewat `serde_wasm_bindgen` (bukan `serde_json`) baru bisa dipastikan pada uji manual B1 (vector dan raw).
11. **Performa/memori vector:** payload `values` dibaca sebagai `Vec<Vec<Option<f64>>>` (+ buffer sementara enum untagged); untuk dataset sangat besar × ribuan kolom ini O(rows × kolom terpetakan) memori. CSR yang dikirim ke CORE hanya memuat nilai non-nol.
12. **Tidak ada fungsi/kode dari NB yang disalin ke AM untuk teks**; tidak ada `any`/TS yang disentuh. `Cargo.lock` AM akan berubah saat `cargo test` pertama (dependensi CORE).
