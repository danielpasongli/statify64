Tidak ada yang memblokir. Keputusan konservatif yang saya ambil (mohon dikonfirmasi pemilik; rekomendasi: pertahankan semuanya):
1. **Label `Text Alpha (smoothing)`**, bukan "Text smoothing alpha" (AGENTS_V2 §3.6): test lama `getByLabelText(/Smoothing Alpha/i)` akan menemukan dua elemen bila label Text memuat frasa itu. Dokumentasi V1 sebaiknya menyebut label sebenarnya.
2. **Teks bantuan Smoothing Alpha diubah** ("... paling besar 999.") agar `getByText(/maksimum 999/i)` hanya menemukan pesan galat. Terbukti memperbaiki test lama "> 999".
3. **Semua test N7 di `options.test.tsx`** (file test satu-satunya milik N7); file itu kini memock store, modal, IndexedDB, sonner, `variables-tab` dan `analyzeNaiveBayes`. Bila ingin dipecah per file, lakukan di fase integrasi/V1.
4. **Peran Numeric efektif** di UI: exclude = `measure === "scale"` dan bukan STRING; candidates = `CandidateCovariates`. Rust (`models/data.rs`, `preprocess_data.rs`) menentukan peran murni dari `measure`, jadi hasilnya sama kecuali kasus ganjil variabel STRING ber-measure scale (UI tidak menampilkannya sebagai Numeric, Rust akan menganggapnya Numeric).
5. **Guard pindah tab** ditambahkan (tidak ada di container v1) dan hanya menahan galat milik tab yang ditinggalkan. `NB_E_COMPLEMENT_MIXED` tidak menahan pindah tab tetapi tetap memblokir OK.
6. `TextFeatureTable` tetap tersimpan `true` walau tanpa Text Features (hanya tampil nonaktif); N8/N4 harus mengabaikannya bila tidak ada Text.
7. Belum ada test container yang memuat data lama dari IndexedDB (mock `getFormData` selalu `null`); `mergeWithDefaults` sudah dites di N5.
