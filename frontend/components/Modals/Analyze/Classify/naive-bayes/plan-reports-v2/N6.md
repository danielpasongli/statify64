## KEPUTUSAN TERBUKA / risiko
1. **Layout dua panel dibuat sendiri.** `VariableListManager` hanya mendukung satu sorotan dan dilarang diubah, sehingga multi-highlight mustahil lewat komponen itu. Konsekuensi: tooltip per item, helper text, dan tata letak vertikal khusus mobile milik `VariableListManager` tidak ada; diganti grid satu kolom di layar sempit. Fungsi inti v1 (drag & drop, urut ulang, panah, double-click, mode saling eksklusif) dipertahankan. Mohon uji manual di UI.
2. **Double-click pertama tetap mengisi Target tanpa cek measurement** (meniru v1, lewat `skipRuleCheck`); drag/panah ke Target memakai aturan nominal/ordinal. Konservatif; bisa diseragamkan bila pemilik mau.
3. **Word-Vector hanya `type === "NUMERIC"`** (kontrak §3.2). Subtipe angka lain (`COMMA`, `DOT`, `SCIENTIFIC`, dst.) tidak bisa masuk slot itu. Bila kolom vektor hasil STWV bertipe lain, perlu diperlonggar.
4. Label "Nama" pada tombol sort diganti "Name" dan tombol "Select All" menjadi "Select All (filtered)" (label UI bahasa Inggris; komponen ini sebelumnya tidak dipakai di mana pun).
5. Daftar kiri me-render semua variabel yang lolos filter tanpa virtualisasi; untuk ribuan kolom vektor masih wajar, tetapi filter dianjurkan.
6. Peringatan dihitung dari `formData` (identitas objek `main` berubah pada tiap perubahan) dan `useDataStore.data`; W-STR memindai sampel 5.000 baris per kolom STRING tiap kali daftar variabel berubah.
7. Memindahkan variabel ke Target/Raw Text/Word-Vector tidak mengubah `SpecificationMode` (hanya Excluded/Candidates yang memicu perpindahan mode, seperti v1).
8. `raw-text-payload.test.ts` menguji fungsi N5 (`buildNaiveBayesTextPayload`) dari folder test milik N6, sesuai catatan tambahan; test tingkat container tetap tugas N7.
9. Tidak ada `any` baru; tidak ada Rust yang disentuh.
