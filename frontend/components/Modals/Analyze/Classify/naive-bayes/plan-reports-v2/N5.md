## KEPUTUSAN TERBUKA / risiko
1. **Kontrak urutan `dataVariables` (butuh N7).** Kolom Text dibaca dari EKOR `dataVariables`: `[target, ...getEffectivePredictors, ...getTextColumnNames(main)]`. Container (`naive-bayes-main.tsx`, milik N7) harus menyusun `slicedData` dengan `selectedVariables = [target, ...predictors, ...getTextColumnNames(formData.main)]`. Tanpa itu payload Text berisi `{source:"none"}`-setara kosong/null. `getTextColumnNames` sudah diekspor untuk itu.
2. **Worker belum meneruskan `text` (milik I1).** `analyzeNaiveBayes` kini mengirim `text` di `postMessage`; `naive-bayes.worker.js` masih memanggil konstruktor tanpa argumen ke-6 (N1 sudah memberi argumen `text`, `undefined` → `None`). I1 harus membaca `text` dari `e.data` dan meneruskannya.
3. **Error tipe di file milik fase lain (terkonfirmasi oleh `tsc` pemilik):** `dialogs/naive-bayes-main.tsx` (`cloneNaiveBayesDefault` tanpa `text`, merge hasil load tanpa `text`; N7 — dapat memakai `mergeWithDefaults`) dan `components/__tests__/options.test.tsx` (literal `NaiveBayesOptionsType` tanpa field v2; N7). `tsc` penuh akan memberi error di sana sampai N7; jest frontend memakai `isolatedModules` sehingga tidak terpengaruh. Saya tidak menyentuh file itu.
4. **`getSlicedData` mengubah teks berawalan angka menjadi angka** (`parseFloat`, `hooks/useVariable.ts`, di luar milik N5). Sel teks mentah seperti `"3 kucing lucu"` menjadi `3` sebelum sampai ke payload (builder men-String-kan hasilnya, sehingga dokumen terpotong). Mengatasinya butuh perubahan di luar lingkup (mis. N7/I1 mengambil kolom teks mentah langsung dari `useDataStore.data`).
5. **Test v1 disentuh:** 4 literal `main` bertipe `NaiveBayesType["main"]` diberi `TextSource/RawTextVar/TextVectorVars` karena tipenya memang diperluas (AGENTS_V2 §12). Ekspektasi tidak berubah. Mohon persetujuan pemilik.
6. **`Text` hanya dikirim untuk jalur raw** (vector/none → `Text: null`), lebih konservatif daripada "selalu `toRustConfig(text)`": konfigurasi preprocessing yang tak terpakai tidak bisa memicu `NB_E_TEXT_CONFIG` di Rust dan payload setara v1 tetap setara. Mudah diubah bila pemilik ingin selalu mengirim.
7. Validasi `TextAlpha`/`TextTopK` hanya aktif bila Text Features terisi (dan Top-k hanya bila `TextFeatureTable` dicentang) agar field tersembunyi tak memblokir OK; `TextTopK` tak sah tetap disanitasi ke 100 saat dikirim. Interpretasi `W-VEC` "Numeric efektif" = `measure === "scale"` bukan STRING; `W-STR` = `type === "STRING"` di predictor efektif; keduanya diminta memakai data dari `useDataStore.data` (baris-demi-baris).
8. **Kekhilafan prosedur:** satu perintah `git diff --stat` (baca-saja) terlanjur terselip pada satu panggilan shell di awal. Tidak ada perintah git lain, tidak ada perubahan repo oleh git. Juga, percobaan `npx jest` memicu skrip postinstall npm yang gagal mengunduh (403/EAI_AGAIN); tidak ada paket yang terpasang/berubah.

9. **Test v1 yang gagal bukan regresi N5.** Test `form kosong (default)` memakai `TargetVar = null` dengan mode exclude, sehingga `getEffectivePredictors` v1 (`name !== target`) mengembalikan SEMUA variabel eligible dan v1 tidak pernah menghasilkan pesan "predictor" pada kondisi ini; kodenya memang tidak berubah untuk kasus itu (hanya menambah pengeluaran Raw/Vector yang kosong).
