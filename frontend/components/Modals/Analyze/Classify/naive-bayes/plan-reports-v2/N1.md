## KEPUTUSAN TERBUKA / risiko
1. **Field v2 di struct sibling, bukan di struct v1.** PLAN menyebut field baru "di `models/config.rs`"; menambahkannya ke `MainConfig/OptionsConfig/OutputConfig/NaiveBayesConfig` merusak kompilasi test lama di `save.rs` (N4) yang memakai literal struct. Pilihan konservatif: struct `*V2` terpisah, config JSON yang sama di-parse dua kali. Fase berikutnya (mis. N4 setelah memiliki `save.rs`) boleh menggabungkannya ke struct v1 bila mau.
2. `TextPayload` tidak ditambahkan ke `AnalysisData` (alasan sama: literal di test `preprocess_data.rs`); disimpan terpisah di `NaiveBayesAnalysis.text`. `run_analysis` (milik N3b) belum menerimanya — N3a/N3b perlu menambah parameter.
3. **Model hanya-Text:** constructor kini meloloskan `predictors_data_defs` kosong bila ada payload Text, tetapi `preprocess_naive_bayes_data` masih menolak "At least one predictor variable is required". N3a/N3b harus menangani (mis. melewati resolusi predictor bila Text terisi).
4. Galat bentuk payload (baris vector tidak rata, jumlah baris Text ≠ data) memakai pesan Indonesia tanpa kode `NB_E_*` karena §11 tidak mendefinisikan kodenya; usul: tambahkan `NB_E_TEXT_SHAPE` di dokumen.
5. `Cargo.lock` NB akan berubah saat `cargo test` pertama (dependensi baru CORE: regex, hashbrown, rust-stemmers, sastrawi-rs). Butuh jaringan crates.io. File tidak saya edit manual.
6. Catatan S4 (`CATATAN_TAHAP2_float_roundtrip.md`): fitur `float_roundtrip` pada `serde_json` CORE belum perlu untuk N1 (resep tidak diserialisasi di fase ini), tetapi wajib dipertimbangkan sebelum N4/export schema 2.0 (Cargo.toml CORE bukan milik N1).
7. Serde tag internal (`source`) pada `TextPayload` dengan `serde_wasm_bindgen`: kompilasi terbukti (`cargo check` wasm32), perilaku runtime dengan objek JS nyata baru terbukti saat uji WASM (B1).

- **NotScored (CATATAN_TAHAP2 §2) untuk N3a:** `align_text_payload`/`vector_to_csr` TIDAK menentukan baris NotScored. N3a/A2 menentukannya di pemanggil: raw null/kosong/whitespace = prediktor missing; vector missing bila semua kolom (payload) bernilai `null` — pengecekan ini harus dilakukan pada `TextPayload` SEBELUM `vector_to_csr` (setelah konversi, `null` dan `0` tidak terbedakan). Complement tanpa prior + baris kosong + tanpa prediktor lain → NotScored. Jangan menambah filter baris-nol di CORE. Case Processing Summary: pisahkan "dibuang karena target missing" dari "NotScored karena prediktor missing".
