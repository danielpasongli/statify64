## KEPUTUSAN TERBUKA / risiko
1. **Presisi f64 pada JSON model**: `serde_json` tanpa `float_roundtrip` bisa menggeser nilai 1 ulp (~1e-16) saat model disimpan/dimuat sebagai string JSON. Dampak praktis dapat diabaikan, tetapi bila Tahap 2 ingin round-trip bit-per-bit, ubah `CORE/Cargo.toml` menjadi `serde_json = { version = "1.0", features = ["float_roundtrip"] }` (di luar file milik fase S4; keputusan pemilik). Jalur objek WASM (`serde_wasm_bindgen`) tidak terpengaruh.
2. **Entri nol eksplisit di CSR**: term yang ada di kosakata dan muncul di dokumen disimpan secara struktural walau nilainya 0.0 (mis. IDF standard = 0). Alasan: menjaga definisi `empty_documents` S3 ("tanpa term kosakata") = baris tanpa entri. `to_dense()` tidak terpengaruh. Konsumen Tahap 2 boleh mengabaikan nilai 0.
3. **`transform` pada array dokumen kosong → `EMPTY_INPUT`**, sedangkan dokumen yang semuanya kosong/whitespace/OOV diperbolehkan (baris nol; berbeda dari `fit` yang menolak "semua kosong"). §3.4 tidak merinci; tafsiran konservatif.
4. **Tambahan publik di luar §3.4**: `output_from_model`, `RECIPE_VERSION`, dan `vectorize` (lama, dipertahankan). Semuanya aditif; API §3.4 tidak diubah. Helper baru di `pipeline.rs` hanya `pub(crate)`.
5. `transform` memvalidasi model (`recipe_version == "1.0"`, panjang vocabulary/idf/doc_freq sama, kosakata tidak kosong, `avg_doc_norm` ada untuk doc_length) → `INVALID_DATA`/`EMPTY_VOCABULARY`; juga memanggil `validate_config` pada `model.config`.
6. `Dictionary` Sastrawi dibangun ulang pada setiap pemanggilan `transform` (biaya tetap per panggilan, bukan per dokumen). Konsumen Tahap 2 sebaiknya memanggil `transform` per batch besar.
7. `doc_length` dengan `avg_doc_norm = Some(0.0)` (semua baris latih bernorma 0) membuat baris transform menjadi nol; konsisten dengan perilaku S3 (tidak ada NaN).
8. `Cargo.lock` tidak diubah (tidak ada dependensi baru).
