## Ringkasan perubahan
1. `config.rs`: enum `StopwordsMethod`, `StemmingMethod`, `TfMethod`, `IdfMethod`, `FormulaStandard`, `Normalization` (`rename_all = "snake_case"`). Alias lama: tf `"none"`→Binary, `"log"`→Sublinear; idf `"idf"`→Standard; `"none"` tetap valid untuk idf, stopwords, stemming. Field baru `formula_standard` (default Weka), `normalization` (default None), `min_term_freq` (default 1) memakai `serde(default)`, jadi JSON v1 tetap diterima. Tambah `from_json_value` / `from_json_str` yang memetakan error parse (nilai tak dikenal, field hilang) ke `INVALID_CONFIG`.
2. `validator.rs`: tambah `validate_config` (ngram_min ≥ 1, min ≤ max, max ≤ 5, `min_term_freq` ≥ 1). `validate(docs, min, max)` tetap: array kosong atau semua dokumen kosong → `EMPTY_INPUT`; dokumen kosong di tengah diperbolehkan.
3. `stopwords.rs`: `build_set` mem-parse JSON stopwords SEKALI. JSON rusak → `INVALID_STOPWORDS` (F11), fallback `unwrap_or_else(|_| vec![])` dihapus. `filter_with_set` dan `filter` (ad-hoc) tersedia.
4. `stemmer.rs`: `stem_batch` membuat `Stemmer` Sastrawi / Porter SEKALI per batch dan memakai cache memo `HashMap<String,String>` (F08). `stem(tokens, &str)` dipertahankan sebagai pembungkus ad-hoc agar test S1 tidak berubah.
5. `pipeline.rs` (baru): `Pipeline` (regex, HashSet stopword, `Dictionary` Sastrawi) + `prepare(&cfg)` + `Pipeline::tokens_batch(&[String])` sesuai §3.4. Satu dokumen masukan menghasilkan satu entri keluaran sehingga indeks sejajar.
6. `lib.rs` CORE: `preprocess_documents` dan `run_pipeline` memakai `prepare` + `tokens_batch`; ekspor `Pipeline`, `prepare`, dan semua enum config.
7. `vectorizer.rs`: parameter `&str` diganti enum. `tf_value` dan `idf_value` menggantikan `match` string. Tidak ada lagi fallback diam-diam `_ => count` (F21). Perilaku angka v1 tidak berubah; `stats.method` tetap berlabel v1 (lihat KEPUTUSAN TERBUKA 1).
8. `STWV/rust/src/lib.rs`: `error_to_js` mengembalikan objek JS `{code, message}` lewat `serde_wasm_bindgen::to_value(err)` (F04); string JSON hanya sebagai fallback bila serialisasi gagal. Gaya CRLF dipertahankan.
9. `error.rs`: hanya komentar `to_json_string` diperbarui (fungsi dipertahankan).
10. Test: `tests/s2_pipeline.rs` baru; `tests/characterization.rs` hanya diubah tipenya (3 baris, lihat bawah), tanpa mengubah ekspektasi.

## KEPUTUSAN TERBUKA / risiko
1. **`stats.method` tetap format v1** ("TF: log, IDF: smooth, Limit: 1000") dan Sublinear diberi label "log" (`TfMethod::v1_label`) supaya `stats_v1_dipertahankan` tetap lulus. Format §3.5 baru dikerjakan di S3.
2. **TF `log1p` dan IDF `plus1` sudah dihitung** di `vectorizer.rs` (satu baris rumus tiap varian) karena `match` enum harus exhaustive. Ini bukan standar/normalisasi/minTermFreq; itu tetap milik S3. `formula_standard`, `normalization`, `min_term_freq` hanya diparse dan divalidasi, tidak berpengaruh pada angka.
3. **`ngram_max ≤ 5` kini ditolak** dengan `INVALID_CONFIG` (diminta §3.1/Tugas 1); sebelumnya v1 tidak membatasi. UI saat ini mengirim 1..10 (`max={10}`), jadi S6 harus meng-clamp 1..5.
4. **Kompatibilitas JSON**: config yang sebelumnya diterima dengan nilai tak dikenal (jatuh diam-diam ke default) kini ditolak. Frontend v1 hanya mengirim nilai sah (`TfMethod` "none|binary|raw|normalized|log", idf "none|idf|smooth") sehingga tetap diterima lewat alias.
5. ~~Risiko kompilasi API `sastrawi-rs`~~ — terselesaikan: kompilasi dan test lulus di mesin pemilik.
6. **Test lama**: 3 baris di `characterization.rs` disentuh hanya karena tipe field berubah (String → enum); ekspektasi tidak diubah.
7. `Cargo.lock` CORE sudah memakai `sastrawi-rs 0.5.3` sedangkan STWV terkunci `0.5.1` (catatan S1 tetap berlaku).
8. `serde_wasm_bindgen::to_value` pada struct menghasilkan objek biasa (bukan `Map`) di versi 0.4; sudah dipakai juga untuk output sukses. Perlu diamati pada uji manual S8 (`error.code` terbaca di UI).
9. Wrapper STWV masih mendeklarasikan dependensi `rust-stemmers`, `sastrawi-rs`, dll. (tidak dipakai langsung); tidak diubah (di luar lingkup).
